# Offline processor

This is an independent MIT-licensed implementation. It does not import or bundle Luscinia. Version 0.2.0 selects a microphone profile for SongBeam, Sipeed D80/MA-USB8, or a validated local JSON array profile. It processes PCM16 WAV inputs in bounded blocks. The profile provides nominal geometry and channel roles; a separate calibration can provide measured mapping, gain, polarity and fixed time offsets for one device. The physical mapping and field accuracy of both built-ins remain unverified.

`songbeam profiles list` and `songbeam profiles show sipeed-d80` display the built-ins. The legacy four-channel command continues to default to `songbeam-4`; select `--source sipeed-d80` for Sipeed. Its `simulated-raw6` layout selects six raw fixture channels; `ma-usb8` selects raw CH0–CH5 from an eight-channel capture, excluding processed CH6 and reserved CH7. The app chooses the layout when the file's channel count matches exactly one option. A custom example is at `processor/examples/tetrahedron-profile.json`; profiles are inert local JSON, bounded and checked before processing.

```sh
songbeam inspect source.wav --source sipeed-d80 --input-layout ma-usb8
songbeam process source.wav --source sipeed-d80 --input-layout ma-usb8 \
  --output /path/to/new-run --format flac --require-mount /path/to/data-drive
songbeam process songbeam-four.wav --source songbeam-4 \
  --output /path/to/other-new-run --format wav
```

`--calibration /path/to/device.json` selects a local calibration with `schema: 1`, `profile_sha256` from `profiles show`, `input_layout`, `calibration_id`, `channel_map`, `gains`, `polarities`, and `fixed_delays_seconds`. The vector length must equal the number of selected microphones. Delays in seconds are converted using the actual input sample rate. This remains **supplied, unverified** until physical calibration is checked. Alternatively, the existing individual calibration flags remain available. Do not mix them with `--calibration`.

The direction output uses local coordinates: +X at 0°, +Y at 90°, and elevation from the array plane. `--orientation-deg` gives the compass bearing of local +X when independently measured. SongBeam reports a signed projection and angle to its array axis, with compatible bearings rather than inventing a unique compass direction. Optional `--known-elevation-deg` and `--source-sector START,END` can restrict SongBeam to a known source plane/sector and record that assumption; a contradictory constraint is flagged. Sipeed reports local azimuth and absolute elevation, with an above/below mirror ambiguity. Near zenith, local azimuth is marked unobservable. Far-field processing does not claim range. `--manual-angle` remains SongBeam's broadside angle; `--manual-azimuth` with optional `--manual-elevation` steers other profiles using local coordinates.

Automatic localization scores short overlapping 0.1-second windows within each 0.5-second processing block by default. `--analysis-window-seconds` and `--analysis-hop-seconds` can change these; the output timeline still follows the input sample clock. Scores are relative evidence, not calibrated confidence probabilities. Brief second-source evidence can yield an experimental second track, and direction tracks can reacquire after silence. Ambiguous or same-direction birds may remain mixed.

`songbeam inspect` reports header consistency, frames, SHA-256, per-channel RMS/DC/peak and silent/clipped channels. `songbeam process` scores profile-derived directions using every selected microphone pair (six SongBeam pairs or fifteen Sipeed pairs), then applies normalized fractional-delay delay-and-sum in bounded blocks. An explicit manual direction bypasses automatic localization. Optional individual calibration values are applied after file-channel selection. The transform reuses each input FFT across output beams and blends a direction change over 20 ms. Output tracks share the original sample timeline. Silent intervals in a second track indicate no stable second direction, not a separated bird. Results contain a manifest, sample offsets, activity and relative direction scores, hashes and processing configuration.

`songbeam analyze` accepts one nonempty mono WAV/FLAC or a flat directory of uniquely named mono WAV/FLAC files and invokes a separately installed BirdNET-Analyzer command once per batch. It checks that every expected result CSV exists even if BirdNET exits zero after a per-file error. It never feeds a raw multichannel WAV through BirdNET's automatic downmix. For batches it writes `possible_cross_beam_overlaps.csv`, flagging same-species detections that overlap in time while keeping every original prediction intact. An overlap can also be two birds of the same species; it is a review cue, not automatic bird counting. Example: `songbeam analyze /path/to/mono-tracks --output /path/to/new-analysis --executable birdnet-analyze --threads 2 --batch-size 8 --require-mount /path/to/data-drive`.

Formats: WAV native-rate PCM24 default (`--wav-subtype PCM_16` or `FLOAT` optional), FLAC native-rate PCM24 at compression level 5 default (`--flac-level 0` through `8`), MP3 mono 192 kb/s CBR default (`--mp3-bitrate 128` or `256` optional). `--mp3-vbr-quality 2` selects optional VBR. FLAC and WAV PCM24 are dithered and quantized from one float signal, then written as identical PCM. MP3 is a listening derivative. The processor uses RF64 for WAV files projected to exceed the RIFF limit. Encoder executables must be installed separately; MP3 requires FFmpeg with libmp3lame.

SongBeam's physical array is linear. A direction score does not establish species, bird count or three-dimensional bearing. Close/same-projection callers, reflections, unequal levels and high-frequency sidelobes may defeat isolation. The second track is experimental. MVDR/LCMV is not implemented because uncalibrated weights can cancel a target; benchmark it against this baseline before adding it. BirdNET detections are model outputs and require separate human review. A failed or canceled file can be restarted with the same command and `--resume`: the prior manifest, source hash, version and settings are checked, and a new sibling output is created. There is no partial-chunk resume. For field storage, pass `--require-mount /path/to/data-drive` and an output directory under that mount; the command verifies mount identity and free space before and during writing.

Offline verification: `uv run pytest -q`, `uv run ruff check src tests scripts`, and optionally `PYTHONPATH=src uv run python scripts/evaluate_fixtures.py /path/to/external-fixtures --output /path/to/new-results.json`. The optional fixture suite uses licensed bird excerpts kept outside Git. To measure runtime on procedural audio, run `PYTHONPATH=src uv run python scripts/benchmark_profiles.py --profile sipeed-d80 --minutes 10 --scratch-parent /tmp` (also supports `songbeam-4` and 1/30 minutes). The benchmark removes only its own temporary files. Synthetic/ideal-array tests do not establish physical channel mapping, enclosure response or field accuracy.

Reproducible checks: `uv sync --extra dev --locked` from this directory, then `uv run pytest -q`. For the recorder's pure WAV helper, run `g++ -std=c++17 -Wall -Wextra -Werror -Icode tests/test_wav_format.cpp -o /tmp/songbeam-wav-test && /tmp/songbeam-wav-test` from the repository root. Compile the Teensy sketch with Teensyduino 1.62 for Teensy 4.1; Arduino CLI needs a temporary sketch folder named `SongBeam4C` with `SongBeam4C.ino` and `WavFormat.h`. No firmware build or output from this repository should be flashed without a physical validation step and a known-good recovery image.
