# Offline processor

This is an independent implementation with an MIT license. It does not import or bundle Luscinia. It reads four-channel 16-bit PCM SongBeam WAV files in bounded blocks. A strict RIFF check rejects truncation, extra bytes and inconsistent frame fields. The file channel map must be supplied explicitly; the candidate physical positions are 0, 45, 75 and 120 mm. Confirm polarity, gains and physical channel order on a real board before claiming directional accuracy.

`songbeam inspect` reports header consistency, frames, SHA-256, per-channel RMS/DC/peak and silent/clipped channels. `songbeam process` scores a one-dimensional direction grid with all six microphone pairs using energy-weighted SRP-PHAT, tracks up to two persistent peaks, and applies normalized fractional-delay delay-and-sum in bounded 0.5-second blocks. An explicit `--manual-angle` bypasses automatic localization; it can be repeated. Optional calibration parameters `--gains 1,1,1,1`, `--polarities 1,1,1,1` and `--fixed-delays-samples 0,0,0,0` are applied after the file channel permutation; only use measured values from the specific assembly. The transform reuses each input FFT across output beams and blends a direction change over 20 ms. Output tracks share the original sample timeline. Silent intervals in a second track indicate no stable second direction, not a separated bird. Results contain a manifest, sample offsets, activity/confidence, hashes and processing configuration.

`songbeam analyze` accepts one nonempty mono WAV/FLAC or a flat directory of uniquely named mono WAV/FLAC files and invokes a separately installed BirdNET-Analyzer command once per batch. It checks that every expected result CSV exists even if BirdNET exits zero after a per-file error. It never feeds a raw four-channel WAV through BirdNET's automatic downmix. For batches it writes `possible_cross_beam_overlaps.csv`, flagging same-species detections that overlap in time while keeping every original prediction intact. An overlap can also be two birds of the same species; it is a review cue, not automatic bird counting. Example: `songbeam analyze /path/to/mono-tracks --output /path/to/new-analysis --executable birdnet-analyze --threads 2 --batch-size 8`.

Formats: WAV native-rate PCM24 default (`--wav-subtype PCM_16` or `FLOAT` optional), FLAC native-rate PCM24 at compression level 5 default (`--flac-level 0` through `8`), MP3 mono 192 kb/s CBR default (`--mp3-bitrate 128` or `256` optional). `--mp3-vbr-quality 2` selects optional VBR. FLAC and WAV PCM24 are dithered and quantized from one float signal, then written as identical PCM. MP3 is a listening derivative. The processor uses RF64 for WAV files projected to exceed the RIFF limit. Encoder executables must be installed separately; MP3 requires FFmpeg with libmp3lame.

The physical array is linear. A direction score does not establish species, bird count or three-dimensional bearing. Close/same-projection callers, reflections, unequal levels and high-frequency sidelobes may defeat isolation. The second track is experimental. MVDR/LCMV is not implemented because uncalibrated weights can cancel a target; benchmark it against this baseline before adding it. BirdNET detections are model outputs and require separate human review. A failed or canceled file can be restarted with the same command and `--resume`: the prior manifest, source hash, version and settings are checked, and a new sibling output is created. There is no partial-chunk resume. For field storage, pass `--require-mount /path/to/data-drive` and an output directory under that mount; the command verifies mount identity and free space before and during writing.

Reproducible checks: `uv sync --extra dev --locked` from this directory, then `uv run pytest -q`. For the recorder's pure WAV helper, run `g++ -std=c++17 -Wall -Wextra -Werror -Icode tests/test_wav_format.cpp -o /tmp/songbeam-wav-test && /tmp/songbeam-wav-test` from the repository root. Compile the Teensy sketch with Teensyduino 1.62 for Teensy 4.1; Arduino CLI needs a temporary sketch folder named `SongBeam4C` with `SongBeam4C.ino` and `WavFormat.h`. No firmware build or output from this repository should be flashed without a physical validation step and a known-good recovery image.
